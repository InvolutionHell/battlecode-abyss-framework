# 游戏规则：UNSW Battlecode 2026 "Abyss"

[English](game-rules.md)

面向实现者的规则摘要。依据是官方文档 <https://game.battlecode.au/docs> 和官方工具包 `unswbc` 的引擎源码（MIT 许可，UNSW CPMSoc，<https://github.com/unswcpmsoc/unswbc>）。内容对应规则版本 **1.2.3**，以及工具包 1.2.3 到 1.2.9；这一区间内引擎、沙箱和编译器逐字节相同。标 **（探针）** 的条目用小型测试 bot 验证过。本页与引擎不一致时，以引擎为准。

更底层的实测（声呐（sonar）细节、虚拟时钟、构建缓存）见 [engine-notes.md](engine-notes.md)（英文）。

## 概览

| 项目 | 值 |
| --- | --- |
| 对局双方 | 两队，各自控制若干条龙（蛇） |
| 进程 | **每条龙一个进程**，队友之间没有共享内存 |
| 棋盘 | 环面（torus），W x H，每边 10-64 格 |
| 对局长度 | 500 回合（0-499） |
| 胜负 | 全灭对方；否则第 500 回合后依次比较：**女王**长度、最长龙、总长度 |
| 单位数 | 每队最多 64 条存活的龙 |
| CPU | 每条龙每回合 100 M 点（按指令计价，虚拟时钟） |
| 内存 | 每条龙 48 MiB |
| 本项目用的语言 | C++20，由评测机的 clang 编译成 WASM（`-O2 -msimd128`） |

## 棋盘

- 网格在两个方向上都首尾相接：从一边走出去会从对边回来。(0, 0) 在左上角，y 向南增大。
- 相邻两格之间的边可以是空、**海藻**（kelp）或**传送门**（portal）。海藻是墙，撞上即死。传送门把龙从配对边的另一侧送出，朝向不变；两端共用一个 id 和一个方向。没有配对的传送门不通往有用的地方。视野穿不过传送门，声呐可以。
- **珍珠床。** 有些格子会刷珍珠。这类格子显示一个倒计时（`pearlIn`；-1 表示永不刷新），视野内的龙都能读到。每回合开始、任何龙行动之前，所有倒计时减 1。减到 0 时，如果该格空闲（没有珍珠也没有龙）就刷出一颗珍珠；无论刷没刷出，都从该格隐藏的区间 [min_gap, max_gap] 中均匀抽取下一次倒计时。
- **镜像床共用一个倒计时。** 地图是对称的（`SYMMETRY` 头：竖直镜像、水平镜像或 180 度旋转），一张床和它的镜像格使用同一个倒计时，所以除非一侧被挡住，刷新总是对称的。看到一张床的倒计时，也就知道了它镜像床的倒计时。
- **珍珠刷新按对局随机播种。** 回放里记录了种子，`unswbc run --seed 0x...` 可以复现一局；加 `--sandbox` 时，bot 自己的随机数也会重复。不存在可以背下来的固定刷珠时间表。
- 正式比赛的地图事先不可见。有竞争力的 bot 需要通用的打法，不能依赖地图数据库、开局库或按地图名调参。

## 龙

- 一条龙至少有 2 节，有头和朝向（从第一节身体指向头的方向）。
- 初始的龙由地图定义。id 按地图文件中的顺序从 0 开始编号，而文件必须两队交替列出，所以 **id 0 和 1 是两只女王**，每队一只。
- 所有内置地图都先列 A 队的龙，但格式并不要求这样；天梯对局还会交换双方，所以大约一半的对局里 B 队拥有 id 0。判断女王不要依赖队伍字母：**一条龙是女王当且仅当它的 id 小于 2；视野中 id 小于 2 的身体属于那一队的女王。**
- **女王整局固定。** 分裂时前半段保留父体的 id，所以分裂后的女王仍是女王。女王死后不会有新女王。分裂出的子龙的 id 既不说明它属于哪队，也不说明谁是女王。
- 初始长度由地图决定（工具包自带的 22 张地图为 2-25），女王不一定是最长的初始龙（例如 Autarky 上每队女王初始长度为 3，而同队另有一条长度为 14 的龙）。在自带地图上，每队初始有 1 到 10 条龙。
- 单位上限：`UNIT_LIMIT`（默认 64）条存活的龙；每个回合块中的 `UNIT_COUNT` 是本队存活的龙数。
- **行动顺序。** 每回合先让珍珠倒计时减 1，然后每条存活的龙按 id 从小到大各行动一次（所以女王最先行动）。本回合早些时候被杀的龙跳过。分裂产生的子龙获得下一个未使用的 id（全局编号），并在同一回合稍后行动。

## 动作（每回合一个）

| 命令 | 效果 |
| --- | --- |
| `MOVE <方向串>`，如 `MOVE NNE` | 多步移动（冲刺）。长度为 L 的龙（L 在移动开始时确定）前 **ceil(L/4)** 步免费；之后每多走一步额外去掉一节尾巴，所以走 x 步花费 max(0, x - ceil(L/4)) 节。付费的一步要求当时长度 >= 3；长度为 2 时这条龙死亡（`noValidAction`）：移动不会被截断，已经走过的步数照样生效。每一步都检查碰撞和珍珠；吃到珍珠长度加 1（在付费步上抵消这一步的花费）。不吃珍珠时最远能走 ceil(L/4) + L - 2 步。 |
| `SPLIT n` | 尾部 n 节变成一条新龙，方向反转（子龙的头是原来的尾巴，背对父体）。父体保留前段、原 id 和本回合的行动。要求 n >= 2、父体保留 >= 2 节、本队未达单位上限；否则父体死亡（`noValidAction`）。子龙获得下一个未使用的 id，作为全新进程（新的初始化块，没有记忆）在本回合稍后行动。 |
| 不发送，或动作非法 | 默认动作是**自杀**（死因 `noValidAction`）。除非有意求死，否则每回合都要发送合法动作。 |

- 按长度的免费步数：L 2-4 -> 1，5-8 -> 2，9-12 -> 3，13-16 -> 4，17-20 -> 5，……，61-64 -> 16。不吃珍珠时的最远距离：L 3 -> 2 步，4 -> 3，8 -> 8，12 -> 13，16 -> 18，20 -> 23。（探针）L 3 走 2 步后长度为 2；走 3 步则以 `noValidAction` 死亡；L 7 走 2 步并吃到 2 颗珍珠后长度为 9。
- **每一步按以下顺序结算：** (1) 付费步先检查能否付费；(2) 朝向转到这一步的方向；撞海藻即死，进传送门则从配对边出来，否则头移到相邻（环绕后的）格子；(3) 先用自己的身体检查目标格（包括尾巴，因为尾巴还没动；冲刺的第 2 步看到的是第 1 步之后的身体），再检查其他龙：如果那里是另一条龙的头，那条龙先死，然后本龙也死；如果是其他身体节，只有本龙死；(4) 头移动过去，吃掉那里的珍珠，若没吃到珍珠尾巴前进一格，付费步再多去掉一节尾巴。一旦死亡，剩余步数和本回合的声呐全部作废。
- **连续分裂**（探针）：子龙可以在同一回合再次分裂，孙龙也在这一回合行动，所以一条很长的敌龙可以在身体中段长出一个新头，并在一回合内发起攻击。
- `MOVE` 和 `SPLIT` 互相覆盖，以 `ENDTURN` 之前读到的最后一条为准。无法解析的行会被跳过，之前的动作保持不变。
- **主动自杀是合法的。** 死去的龙会掉落珍珠（见下文），所以一条短龙可以有意死在队友旁边来喂它。本项目发布的 bot 在终局喂食中用到了这一点。

每回合还可以选择发送：声呐（protocol 3：最多四条 `SONAR <方向> <u64>` 射线，每个方向一条；或旧式的 `SONAR <u32>`，沿朝向发出）、`INDICATOR`、`LOG`、`DOT`、`LINE`（调试输出），最后是 `ENDTURN`。发送 `PROTOCOL 3`（官方 helper 会发）后，从下一回合起启用 `ECHOES` 和超过 32 位的值。每次进程启动都会收到初始化块（`ID`、`TEAM`、`MAP W H`、`UNIT_LIMIT`）；每个回合块包含 `ROUND`、`DIR`、`LENGTH`、`UNIT_COUNT`、`NUM_MSGS` 及其值、`ECHOES`、视野内的 49 格、`DRAGON_BODIES` 和边。对局结束时引擎关闭 stdin。

## 死亡

- 撞海藻：`HitWall`。撞自己的身体，包括尾巴（也包括退回颈部）：`HitSelf`。撞别的龙的身体：`HitOtherBody`。
- 头碰头（无论队友还是敌人）：**双方**都死；被撞的一方先死，并先掉落珍珠。
- 动作非法或缺失、冲刺付不起、非法分裂、崩溃：`noValidAction`。
- **超时即死亡**，即使已经输出并刷新了合法动作（探针：在 `--sandbox` 下先 `MOVE` 并刷新，然后进入忙循环，结果是 "exceeded CPU limit"，以 `noValidAction` 死亡）。
- 长度为 L 的龙死亡时，在它死时所在的身体上掉落 ceil(L/2) 颗珍珠（头、隔一节、下一节……）。格子的倒计时不变。
- **女王死后，在本局剩余时间里的第一项平局判定中按长度 0 计算。**

## 感知与通信

- **视野：** 以头为中心的 7x7 方格（切比雪夫距离 <= 3，可环绕，不穿过传送门）：格子（珍珠、珍珠倒计时）、边，以及其中每一节龙身，格式为 `team id x y facing isHead`。因此两只女王都能凭 id 一眼认出。
- **声呐是唯一的通信方式。** 一条射线携带一个 u64（protocol 3），在移动*之后*从头部沿选定方向发出，每回合每个方向最多一条（按 N、E、S、W 的顺序发出）。与朝向相反的射线从尾巴发出，沿尾巴的方向前进。射线穿过传送门和环绕边界，遇到海藻停止（值丢失），或者停在遇到的第一节龙身上（包括发送者自己），进入那条龙的收件箱，不分敌我。如果在 W + H 格内什么都没碰到，或者发送者本回合死亡，射线丢失。
- 收件箱在接收者的下一个回合读取：id 更大的龙在同一回合就能收到，id 更小的龙下一回合收到。消息不带发送者 id 或队伍。下一个回合块会告诉发送者每条射线停在了什么上（`ECHOES`：海藻 / 友方 / 友方头 / 敌方 / 敌方头 的计数）。
- 没有共享内存：每条龙是独立进程，必须自己重建对地图和队伍的认识。敌人能读到打中自己的射线，也能注入任意值，所以收到的每个值都不可信。射线的精确机制见 [engine-notes.md](engine-notes.md#1-sonar)（英文）。

## 胜负

1. **全灭：** 某队失去最后一条龙的那个回合，对局结束，该队输（两队在同一回合全灭则平局）。
2. **第 500 回合之后**依次比较：(a) **更长的女王**（id 0 对 id 1；死去的女王按 0 计，所以任何活着的女王都胜过死去的女王）；(b) 最长的存活龙；(c) 总长度；(d) 平局。`unswbc run` 会打印由哪一项决出胜负，例如 "(longer queen, 12 to 5)"。

规则 1.2.3 之前，第 500 回合的判定只有（最长龙，总长度）。自行计算胜负而不读取引擎结果的工具，必须使用现行顺序。

## 天梯与比赛（简述）

- **排位**（ranked）天梯对战是在排位地图池中随机抽图的 5 局，会更新评分；**非排位**（unranked）对战在每张选定的地图上打一局，不改变任何评分。整场对战中每队的颜色不变。
- 评分是经过 Kalman 滤波的 Elo，按提交版本和按地图分别记录（一个总评分加每张地图的偏移，各自带均值和不确定度）。期望得分中先手方（拥有 id 0 的一方）有 +20 的评分加成，这也是固定的种子和边不能当作中立测试集的原因之一（见 [../methodology.md](../methodology.md)，英文）。
- 提交物是不超过 4 MB 的 zip，`bot.toml` 位于顶层。
- 2026 赛季有三场淘汰赛（Sprint、Qualifier、Grand Final），全部使用事先不可见的地图。

## 评测限制

| 限制 | 值 |
| --- | --- |
| 每条龙每回合 CPU | 100 M 点（按 WASM 指令计价，见下） |
| 每条龙内存 | 48 MiB |
| 每条龙线程数 | 1（`std::thread` 会抛异常） |
| 兜底 | 每回合 1 s 真实 CPU / 10 s 墙钟（只针对绕过计价器的 bot） |

- bot 在 WASM 沙箱中运行。`unswbc run --sandbox` 可在本地复现（`-v` 打印每回合的输出）。普通的 `unswbc run` 没有 CPU 限制，只有每回合 10 s 墙钟，所以 CPU 检查必须用 `--sandbox`。
- 点数耗尽的回合什么也交不出去，龙随即死亡；第一回合同样计费，包括进程初始化。计价器从读取回合块开始，到 `end_turn()` 中刷新输出为止；`end_turn()` 之后做的工作记到下一回合。
- **价格：** 常量、局部和全局变量、比较、整数和浮点运算（包括 sqrt 和 min/max）以及类型转换各 1 点；读写内存、分支和每条 SIMD 指令各 2 点（4-16 个通道只花两条标量指令的价钱）；除法、取余和 `br_table` 3 点；`call` 4 点；间接调用 6 点；`memory.copy` / `memory.fill` 10 点加每 8 字节 1 点；`memory.grow` 50 点。宿主调用：每次写 stdout 或 stderr 2.5 M 点加每字节 4 000 点，读 stdin 每字节 6 点，随机字节 40 000 点加每字节 3 点，打开文件 40 000 点。
- **沙箱时钟是虚拟的：1 点 = 1 ns。** 100 M 点的回合在 `steady_clock` 上是 0.1 s，而不是 1 s（1 s 是真实 CPU 的兜底）。搜索预算要按这个时钟来定。
- 输出很贵：每回合只写一次。C/C++ helper 在 `init` 中设置全缓冲输出，并在 `end_turn` 中刷新；不要设置 `std::unitbuf`。评测机每队每局最多保留 500 000 行日志、指示和绘图，以及 16 MB；指示文字截断到 512 个字符。
- C/C++：clang 20，`-std=c++20` / `-std=c17`，`-O2 -msimd128`，libc++ 和 wasi-libc，不能用外部库（以源码形式并入）；使用 `__DATE__`、`__TIME__`、`__TIMESTAMP__` 会导致构建失败。Python bot 使用 CPython 3.13，标准库有删减，另有 NumPy。
- **确定性：** 对局种子决定珍珠刷新和每条龙的随机数。龙只能从沙箱获得自己独有的随机数（WASI `random_get`，按龙播种）。不调用 `srand` 的 `rand()`、默认构造的 `std::mt19937` 或 `srand(time(NULL))` 会让每条龙得到相同的序列。

## 本项目的 CPU 线：95 M

评测机的硬上限是每回合 100 M 点。发布的 bot 把 **95 M** 当作自己的硬线：

- 搜索以虚拟时钟上的 75 M 点为截止时间（典型回合总计约 78-80 M，大地图满单位时观测到的最坏回合约 82-86 M）；
- 每个可能看到虚拟时钟越过 95 M 的检查点（搜索之前的策略、声呐阶段、最后的刷新）都会立刻兜底：搜索之前由策略走代价最低的合法一步，之后的检查点保留已经决定的动作，并丢掉声呐射线，至少给写出动作留下 3 M 点；
- 这个兜底由单元测试覆盖，并用一个强行把时钟推过这条线的 "burn" 测试构建验证。

细节与实测见 [engine-notes.md](engine-notes.md#3-the-95-m-line-and-the-forced-fallback)（英文）。

## 规则变更记录

- **规则 1.2.3（女王更新）：** 龙 0 和 1 是女王；第 500 回合后先比女王长度（死亡 = 0），再比最长龙，再比总长度，最后平局。冲刺的前 ceil(L/4) 步免费（之前是 1 步）。天梯评分改为按提交版本、按地图的 Kalman-Elo。
- **工具包 1.2.3 到 1.2.9：** 没有规则变化；只有版本号、回放查看器和内置模板地图不同。同一个 bot 在相同种子上（检查了三个种子）在两个版本中产生完全相同的事件流。
- **更早：** 珍珠刷新改为按对局随机播种（之前是每张地图固定的时间表）。
